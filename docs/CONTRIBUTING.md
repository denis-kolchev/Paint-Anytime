# Contributing

Bug reports and feature suggestions are welcome through GitHub issues. Please describe the expected behavior, actual behavior, and steps to reproduce a problem, including the device and operating system version when relevant.

## Pull requests

Keep changes focused and explain their purpose and how you checked them. For substantial changes, open an issue first to discuss the approach.

Code, documentation, artwork, and other material submitted for inclusion in the project require acceptance of the [Contributor License Agreement, version 1.0](CLA.md). This lets the repository remain under `AGPL-3.0-only` while permitting separately licensed official App Store builds, as described in [LICENSING.md](LICENSING.md).

Read the CLA, then post the following statement in each pull request from your own GitHub account, replacing the placeholders with the full commit SHA and your name:

> I have read and agree to the Paint Anytime Contributor License Agreement version 1.0 in docs/CLA.md as of commit <full commit SHA>. My agreement covers my contributions in this pull request, including subsequent revisions I submit to it. I confirm that I have the authority to grant these rights. Name: <your name>.

Each contributor to a pull request must provide their own agreement. If an employer or another organization owns the contribution, obtain its authorization before agreeing and identify that organization in your statement. If you cannot grant the required rights, explain this before submitting material for inclusion.

A `Signed-off-by` line or DCO sign-off does not replace this explicit CLA acceptance. Merely opening an issue or pull request does not establish acceptance. General bug reports and feature suggestions do not require a CLA; code or assets supplied through an issue for inclusion do.

## Third-party material

Identify any third-party code, dependencies, or assets in your contribution, including their origin, license, and required notices. Do not claim rights to material you do not own or have authority to license. Material that cannot be distributed under the project's source and official App Store licensing arrangements must not be incorporated without a separate compatible permission.

## Maintainer checklist

Before merging a contribution:

- Confirm explicit CLA acceptance from every contributor and retain the statements in the pull request record.
- Verify that each statement identifies the CLA version and repository commit containing the accepted text, and that any necessary organizational authorization is recorded.
- Check third-party material and preserve required notices; CLA acceptance does not override third-party licenses.
- If the CLA terms change, obtain explicit acceptance of the new version before relying on those terms. Do not assume the CLA covers earlier contributions without an agreement identifying them.
